# Project Requirements: Data Visualization Dashboard

## 1. Project Goal

Build a dashboard for a specific dataset.

The dashboard should help users explore the dataset, understand important patterns, and communicate a clear data story through appropriate visualization techniques.

## 2. Accepted Tools

Use one of the following tools, or an equivalent dashboard/visualization platform:

| Tool group | Examples |
|---|---|
| BI tools | Power BI, Tableau, Apache Superset |
| Python dashboard tools | Plotly, Dash, Streamlit |
| Equivalent tools | Any tool that can build an interactive dashboard and export/share the result |

## 3. Data Source Requirement

The dataset must be findable on Google Dataset Search.

For this project, remember to keep the dataset source link or citation so it can be included in the report and presentation.

## 4. Deliverables

| Item | Description |
|---|---|
| Source code / project file | Dashboard source code, or project file if using Power BI/Tableau. |
| Presentation slides | Slides used for the dashboard demo. |
| Report | A report that clearly analyzes the visualization techniques and course guidelines applied in the dashboard. |

## 5. Report Guideline: "Technique Application" Section

The report must include a clear analysis of visualization techniques and principles covered in the course, and explain how they were applied to each chart or dashboard page.

Use the structure below. Add one subsection for each relevant chapter.

### Suggested Structure Per Chapter

#### Chapter X: Chapter Title

##### Techniques / Principles Applied

- List the relevant techniques or principles from the chapter.
- Use references such as X.1, X.2, and so on if the course material uses numbered items.

##### How Applied in the Dashboard

- Explain which dashboard page or chart uses the technique.
- Explain why that chart type, encoding, layout, or interaction was chosen.
- Include screenshots if useful.

##### Notes / Adjustments

- If the dashboard deviates from the theory, explain why.
- Mention practical constraints such as data quality, tool limitations, or readability trade-offs.

## 6. Suggested Chapter Coverage

You do not need to cover every chapter. Only include chapters relevant to the dashboard. Irrelevant chapters may be skipped or briefly explained.

| Chapter | What to Address in the Report |
|---|---|
| Ch. 1 | Why the dataset was chosen; role of visualization in the problem; visualization purpose such as exploratory or explanatory analysis. |
| Ch. 2 | Data types: nominal, ordinal, quantitative; visual marks such as points, lines, and areas; visual channels such as position, size, and color; rationale for encoding each variable. |
| Ch. 3 | Pre-attentive processing; Gestalt principles such as proximity and similarity; magnitude estimation such as length vs. area vs. angle; which charts use these ideas and whether the choices are appropriate. |
| Ch. 4 | Chart types for amounts, distributions, proportions, relationships, and trends; coordinate systems; whether uncertainty is visualized. |
| Ch. 5 | If graph data is used: graph data properties, layout mechanism such as force-directed or hierarchical layout, and node/edge representation. |
| Ch. 6 | Proportional ink; handling overlap; color palette and accessibility; multi-panel design; titles and captions; data-context balance; avoiding unnecessary 3D charts. |
| Ch. 7 | If maps are used: map visualization type, projection/geocoding foundation, and how data is encoded on the map. |
| Ch. 8 | Interaction techniques: filter, zoom, select, change view; animation if used; tools/libraries used. |
| Ch. 9 | Story structure; storytelling principles; narrative style; relationship between guided story and user exploration. |
